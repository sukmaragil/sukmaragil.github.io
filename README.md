# Sukma Ragil — personal site

A static personal site + blog built with [Jekyll](https://jekyllrb.com), hosted free on **GitHub Pages**. GitHub builds the site automatically every time you push — no manual export step.

---

## Folder structure

```
.github/workflows/       CI deploy + the open_feedback flag
_config.yml              Site settings (title, links, baseurl)
index.html               Home page
work.html                Experience page  (content from _data/jobs.yml)
projects.html            Projects page    (content from _data/projects.yml)
blog.html                Blog index (auto-lists everything in _posts/)
guestbook.html           Guestbook page (visitor sticky notes)
_layouts/
  default.html           Shared header / nav / footer
  post.html              Layout for a single blog post
_data/
  jobs.yml               Your work history — edit here
  projects.yml           Your projects — edit here
_posts/                  One Markdown file per blog post
assets/css/style.css     All styling
assets/js/guestbook.js   Guestbook behavior
```

## ✍️ How to publish a new blog post

1. Create a file in `_posts/` named `YEAR-MONTH-DAY-title.md`, e.g.
   `_posts/2026-06-20-my-new-post.md`
2. Start it with this front matter, then write the body in Markdown:

   ```markdown
   ---
   layout: post
   title: "My New Post"
   date: 2026-06-20
   read: "5 min"
   excerpt: "One or two sentences shown on the blog index."
   ---

   Write your post here. Plain paragraphs, **bold**, _italic_,
   `code`, lists, ## headings, > quotes — all standard Markdown.
   ```
3. Commit and push. The post appears at `/blog/my-new-post/` and on the blog index automatically (newest first).

That's the whole workflow — no rebuild on your machine required.

## 🧰 How to update work history / projects

- **Work:** edit `_data/jobs.yml` — copy a block to add a role.
- **Projects:** edit `_data/projects.yml` — copy a block to add a project.
- **Home intro & focus areas:** edit `index.html`.
- **Name, social links, email:** edit `_config.yml`.

Push the change and the live site updates.

## 📌 The guestbook

Visitors pin sticky notes at `/guestbook/` — no login, published instantly.

**Out of the box it runs in demo mode:** notes save to each visitor's own browser, so people see only their own. Good for trying the design; not a real shared wall. A blue notice on the page says so, and it disappears automatically once you do the step below.

### Turning the input box on and off — `open_feedback`

Whether visitors can post is decided **at deploy time by CI**, not by editing the site.

```
open_feedback = true    the input box is rendered; visitors can post
open_feedback = false   the input box is not rendered at all
```

When it is `false` the bottom bar simply isn't in the page — no notice, no disabled field. Existing notes stay on the wall.

**Persistent** — Repo → **Settings → Environments → `github-pages` → Environment variables**, name `OPEN_FEEDBACK`, value `true` or `false`.

**One-off** — Repo → **Actions → Deploy site → Run workflow**, pick from the dropdown.

Unset means `true`. `open_feedback` in `_config.yml` is only the default for local previews.

### Making it shared (~10 minutes, free)

A static site can't store data itself, so the wall needs one free external database. [Supabase](https://supabase.com) has a free tier that never expires.

1. Create a Supabase account and a new project.
2. In the project, open **SQL Editor** and run:

   ```sql
   create table guestbook (
     id bigint generated by default as identity primary key,
     name text not null default 'anonymous',
     message text not null,
     color text not null default '#fff3bf',
     created_at timestamptz not null default now()
   );

   alter table guestbook enable row level security;

   -- anyone may read
   create policy "public read" on guestbook
     for select using (true);

   -- anyone may post, with length limits enforced by the database
   create policy "public insert" on guestbook
     for insert with check (
       char_length(message) between 1 and 240
       and char_length(name) <= 32
     );
   ```
3. In Supabase go to **Project Settings → API** and copy the **Project URL** and the **anon public** key.
4. Paste them into `_config.yml`:

   ```yaml
   supabase_url: "https://xxxxxxxx.supabase.co"
   supabase_anon_key: "eyJhbGci...."
   ```
5. Push. The wall is now shared by every visitor.

The anon key is safe to publish — it is designed for browser use, and the policies above allow only reading and posting notes, nothing else.

### Moderating

Notes appear immediately (auto-publish). To stop accepting new ones entirely, set `open_feedback` to `false` as described above. The page already blocks empty notes, anything over 240 characters, URLs (the most common spam), and rapid repeat posting. To remove a note, open **Table Editor → guestbook** in Supabase and delete the row.

## 🚀 Deploying to GitHub Pages

This site deploys through GitHub Actions (that is what makes the `open_feedback` flag possible).

1. Create a GitHub repository and put **the contents of this folder** at the repo root — `_config.yml`, `index.html`, `_posts/`, `.github/` and the rest at the top level, not inside a `jekyll-site/` subfolder. Make sure the hidden `.github` folder comes along. If you also want the standalone guestbook page, put that folder alongside them as `guestbook/`.
2. **Repo → Settings → Pages → Build and deployment → Source: _GitHub Actions_.** (Not "Deploy from a branch" — the workflow handles the build.)
3. Push to `main`. Watch it under the **Actions** tab; the site is live about a minute later.

Every later push to `main` redeploys automatically — including new blog posts.

This is the only workflow that deploys to Pages, by design: a repo has one Pages site, so a second deploying workflow would overwrite what the first published. If `guestbook/index.html` is present it is injected with your Supabase keys and published at `/guestbook/` in the same deploy; see `guestbook/README.md`.

### Pick the right `baseurl` in `_config.yml`

- Repo named **`<username>.github.io`** → site is at `https://<username>.github.io/`
  Leave `baseurl: ""`.
- Any **other repo name** (e.g. `portfolio`) → site is at `https://<username>.github.io/portfolio/`
  Set `baseurl: "/portfolio"` so links and CSS resolve correctly.

## 💻 Previewing locally (optional)

You don't need this to publish, but to see changes before pushing:

```bash
gem install bundler jekyll
bundle install
bundle exec jekyll serve
# open http://localhost:4000
```

(`preview.html` in this folder is only a rough static mock-up of the look — the real pages are generated by Jekyll from the files above.)
